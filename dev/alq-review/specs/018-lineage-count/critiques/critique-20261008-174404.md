## Executive Summary

The problem is real and well evidenced: three named defects (the count restarting on any commit, the double
count, the hunk as unit), each with a walked sequence that fails today. The design follows the accepted ADRs
without reopening them, deletes the old hunk hold instead of keeping it beside the new one, and the contract's
28 sequences give a concrete test list. The constitution check is honest: the two places where a count starts
again without the user are named in Complexity Tracking.

Three things must be settled before tasks. (1) The spec promises "zero ways for an agent to lower the count"
while it accepts a file move, a move-and-reword, and keys everything on the branch name, so a new or renamed
branch is a fourth way. (2) The plan's own measurement may show the character diff does not fit the hook's 60 s,
and the plan says it "stops there" with the options undecided; a hook that times out is not a refusal, so that
is a fail-open path today. (3) The data model does not say what a merged lineage does with the release record,
yet one of the 28 sequences (merging a released lineage) depends on it.

Seven decisions the user has not made are written into the plan as if settled; they are user-visible and need
a yes/no.
