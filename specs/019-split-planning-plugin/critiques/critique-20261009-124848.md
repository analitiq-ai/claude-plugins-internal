## Executive Summary

The spec and plan are sound in direction. Telling review the spec at launch removes the one real coupling between
planning and review, and the two-PR order keeps behaviour changes out of the rename noise. The ledger change is one
added field, so rollback is a revert. Three gaps block tasks. (1) A PR with a round awaiting assessment on the day
the new gate ships hits a dead end: the assess launch is refused for want of a binding, and the review launch is
refused for want of an assessment. (2) The planning workflow's new `issue` input is required, but the rescope entry
has no issue to give. (3) The shipping order puts a PR on a #63 branch (the new plugins' Spec Kit projects) before
the code, so today's gate reviews it, and today's gate refuses any #63 branch that doesn't hold the folder #63's
location comment names. Each was found by reading the code; none was run.
