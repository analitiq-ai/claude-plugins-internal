# Contract: the ledger record (core, PR B)

Owner: `core/src/contracts/ledger.ts` (Zod: `LedgerEvent`, `eventFile`), the fold and writes in `core/src/state.ts`;
JSON Schema `core/schemas/ledger-event.schema.json` generated by `core/scripts/write-schemas.ts` (root ADR-0003 d3).
Writer: reviewer's hook as the reviewer App, through core only (P6, ADR-0011 d1). Readers: reviewer's hook (session
App's client) and the orchestrator (its own clients), through `readState` only. Decided by reviewer ADR-0011 and
ADR-0013; not restated here.

## Layout

Branch `ledger` of the served repo, created with its three rulesets at setup (orchestrator `README.md` step 6). A
story's events are the files of `issues/<n>/`, flat, one event per file, named `eventFile(event)`. A file's content
is the event's JSON, keys sorted, two-space indent, trailing newline.

## Events

`v: 1` on every event. The fold accepts every `v` ever written: a change that would reject an event already on
`ledger` adds a new `v` and narrows no old one, since events are permanent and a rejected old event would tamper
its story; frozen `v: 1` histories stay in core's tests. Payload types are `core/src/contracts/snapshot.ts`'s. `<since>` is a `Time` written
`YYYYMMDDTHHMMSSZ`; `<h(x)>` is the SHA-256 hex of `x`'s UTF-8; `<r>` is `<stage>-<n>` of a `RoundId`. Ids, runs and
refs match `[A-Za-z0-9._-]+`.

| kind | content | file | applies when (else the commit is invalid) |
|---|---|---|---|
| `round` | `{kind, v, round: Round}` (`Round` gains `run` and `findings`, R4) | `round.<run>.json` | no round with its `(stage, n)` or `run` |
| `ruling` | `{kind, v, ruling: Ruling}` with `commits: []` | `ruling.<r>.<h(key)>.json` | its round is in `rounds`; `(round, key)` not ruled |
| `ruling-commit` | `{kind, v, round: RoundId, key, commit: sha40}` | `ruling-commit.<r>.<h(key)>.<commit>.json` | its ruling is in `rulings`, is FIX, and its `commits` lacks `commit` |
| `pushback` | `{kind, v, pushback: Pushback}` | `pushback.<r>.<h(key)>.json` | its round is in `rounds` |
| `hold` | `{kind, v, hold: {id, kind, since, question, spec_pr}}` | `hold.<id>.<since>.json` | no row, or its row RELEASED (reopened in place); a `rescope` with `spec_pr` set also when its row records another `spec_pr` or none, OPEN or not (ADR-0013 d5) |
| `release` | `{kind, v, release: {id, since, released, released_by}}` | `release.<id>.<since>.json` | the row `id` is OPEN with that `since` |
| `release` of a tamper | `{kind, v, release: {id: "tamper-<oid>", since: null, released, released_by}}` | `release.tamper-<oid>.json` | `tamper-<oid>` is derived and unreleased |
| `gates` | `{kind, v, ref, gates: Gates}` | `gates.<ref>.json` | always (replaces the section) |

`Hold` rules beyond today's (R8): `question` set on `escalation`, `claim` and a verdict-placed `rescope` (its
`spec_pr` null), null otherwise. `tamper-` is no `HoldKind` row: the fold derives it.

`Round` rules (R4): `findings` is one `RoundFinding {key, file, line}` per finding the round's reviewers reported,
`key` as `Ruling.key`, `file` and `line` as `Finding`'s, no text (ADR-0016 d2); keys unique within the round;
non-empty exactly when `result` is DIRTY. A `ruling`'s and a `pushback`'s `key` names one of its round's `findings`.
The assessor's facts read earlier rounds' finding counts and positions from them, since no round report outlives
its run (FR-004, FR-026). Added within `v: 1`: no round event was on any `ledger` before it.

## Fold

`readState(reader, repo, issue, shared): StateReading`. `head` is the `ledger` ref's oid read first; every history
page is read against it. Commits touching `issues/<n>/` are taken oldest first and classed:

| class | signature | author | change to the directory | effect |
|---|---|---|---|---|
| event commit | `isValid && wasSignedByGitHub` | `[shared] reviewer_app_login` (REST login) | adds only; every file an event whose name is `eventFile(event)` and that applies | its events, in kind order of the table above, then by name |
| clearance | `isValid && wasSignedByGitHub` | `roleOf` = `admin` | deletes only; every deleted file one an earlier invalid commit added or changed | none |
| invalid | any other | any | any | none; derives `tamper-<oid>` |

Each event is read from the commit that added it (the blob at that commit), so a later in-place change by an
invalid commit changes no event. After each event commit the snapshot passes `Snapshot`'s contract. A tamper's
`remaining` is the files its commit added or changed that exist at `head`.

```ts
type StateReading = {
  head: string;                       // ledger oid the fold was read at; every write names it
  snapshot: Snapshot | null;          // null: no directory
  held: boolean;
  causes: StateCause[];
  tamper: Tamper[];
  newest_round: Round | null;
  pushed_back: ReadonlyMap<string, RoundId>;
  releasable: Releasable[];           // open holds the release rule releases now
  startable: boolean;                 // every open hold and every unreleased tamper releasable
  reset: CommentAt | null;
};
type StateCause = { cause: "tampered"; commit: string; remaining: string[] } | { cause: "open_hold"; id: string };
type Tamper = { commit: string; at: string; remaining: string[]; released: boolean; releasable: Releasable | null };
```

Release rule: today's (`releaseOf`, admin = writer role, `questionTag` for an escalation's answer, `/codeworks
reset`), its floor the placing commit's `committedDate`; a tamper's floor is the earlier of its commit's
`committedDate` and that of the first GitHub-signed commit after it on `ledger` (an invalid commit's date is its
author's; its clearance is such a commit), and it is releasable only with `remaining` empty (FR-024).

Errors: `LedgerMissing` (no `ledger` ref; message names orchestrator `README.md` step 6), `BoardNotVisible`,
`GitHubUnanswered`, and any answer not of the shape asked (incl. GraphQL and REST disagreeing on the commits): all
could not run.

## Writes

Each takes the run's `reading`, commits at most once with `createCommitOnBranch` (`expectedHeadOid:
reading.head`, additions only, headline `issues/<n>: <kinds>`), and returns the reading after its commit. One
write's events are one commit: a round and the holds its report places, a gates section and the holds its counts
place, and every release of one claim land together or not at all (ADR-0011 d1, ADR-0013 d4, FR-015).

| function | events | refuses (`StateWriteRefused`, committing nothing) |
|---|---|---|
| `writeState(r, w, repo, issue, shared, reading, next, placements)` | `round`, `ruling`, `ruling-commit`, `pushback` from `checkTransition(reading.snapshot, next)`, new rounds' `at` from `w.now()`; a `hold` (`spec_pr` null, `since` from `w.now()`) per placement `{id, kind, question}` whose row is not OPEN; an OPEN row is left as it is | transition breaks; `next`'s holds or `gates` differ from `reading`'s; a `claim` or `shim` placement (`recordGates` places them); a `rescope` placement with a spec PR (`placeRescopeHold`); an `escalation` or `rescope` placement with no question |
| `placeRescopeHold(…, reading, specPr)` | `hold` (`rescope-<issue>`, `spec_pr: specPr`, no question); none when the row records `specPr`, released or not (ADR-0013 d5) | — |
| `recordGates(…, reading, ref, gates, openings)` | `gates` + a `hold` for each opening not OPEN | — |
| `releaseOnClaim(…, reading)` → `ClaimRelease {released, reset}` | a `release` per releasable hold and releasable tamper | an unreleased tamper not releasable, naming its `remaining` and the release |

Which write places each hold: one a round's report places (`escalation-`, `pushback-`, `audit-`, a verdict's
`rescope-`) is a placement of that round's `writeState`; a spec PR's `rescope-` is `placeRescopeHold`'s; `claim-`
and `shim-` are `recordGates`'s. There is no `placeHold`: a hold with no round is `writeState` with `next` the
reading's snapshot.

Every write refuses while an unreleased tamper stands, except `releaseOnClaim`'s commit when every such tamper
is releasable, which is the write that releases them (FR-024). The refusal names: a repository admin's deletion on
`ledger` of `remaining`, then a Ready move on `[shared] board` and an admin's comment after the invalid commit,
then the claim.
Events whose file is already in the fold are dropped; with none left nothing is committed (a retry, FR-016).

After the mutation: `StateWriteUnsigned(oid)` unless `signature.isValid && signature.wasSignedByGitHub`; on
`GitHubRefused`, `StateStale` when the `ledger` ref has moved from `reading.head`, else the refusal as it came. On
`StateStale` the caller reads `issues/<n>/`'s history from the new head: untouched since `reading.head`, the
reading stands with `head` re-pointed and the commit is retried; touched, it reads and decides again (R3).
