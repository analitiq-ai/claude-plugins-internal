## Executive Summary

The ledger rescope resolves most of the 2026-10-30 findings. E4 (lost writes) is now covered by `expectedHeadOid`
on every write. E1 (per-branch passes), E5 (ancestry, FR-021) and E6 (count + hold in one commit) are fixed. P4
(`off`) is FR-019, P5 is gone because reviewer posts nothing, and E12 is closed by `core/src/session-record.ts` on
main. E8 is already met by core's `runGit` (`core/src/git.ts:24-25`). Three must-address items remain:

1. The claim step runs first on **every** hook entry. A GitHub outage or a missing `ledger` then blocks Read/Glob
   and even the `reviewer off` prompt.
2. The gates section's "one branch per story" rule contradicts US3-1, FR-014 and quickstart #20, which pass a
   second `42-us*` branch.
3. The plan never says which hook implementation is live on main between story PRs. US1 deletes `ledger.py`,
   which `gate.py`, `policy.py`, `hookio.py`, `claimgate.py` and `shimgate.py` import, before US2 builds the
   after-commit check.

The rest are recommendations on cost, tamper-floor robustness and schema evolution.
