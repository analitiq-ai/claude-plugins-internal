## Executive Summary

The problem is real and well-evidenced (workflow.yml has no `adr` step; ADR-0009 accepted but never built). The design is
sound in shape: core owns the list and `adr`, a script decides, the model only judges, could-not-run is its own
outcome. The weak point is the user's **ruling** path. Verified against Spec Kit's engine and `drive_workflow.py`, it
has four defects that would make valid runs stop, or let a model forge a user's overrule: the ruling input persists
into the after-tasks check, it is validated against a judge that re-runs nondeterministically on every resume, notes
have no single writer outside the ask→decide window, and failures at the ask/judge steps reach the skill unhandled.
All are fixable inside the current design.

## Engineering Lens Findings 🔬

### Architecture Soundness
| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E1 | 🎯 | `adr_ruling` outlives its check. The engine merges resume inputs into persisted inputs (`engine.py:1159–1163`), and `_step_env` reads `inputs.json` (`drive_workflow.py:86–89`). A plan ruling therefore reaches the after-tasks `decide`, where "a ruling that names no departure the judge named in this check is refused (exit 1)" (artifact-grammar.md). A valid run fails at `adr-tasks-decide` when tasks don't touch the ruled path. | Drop the workflow input. `drive_workflow.py resume` exports `ADR_RULING` only from the current resume argument, not from `inputs.json`. Also: a ruling already present as a note is satisfied, not refused. |
| E2 | 🎯 | Ruling is validated against a re-run judge. A resume re-runs the whole top-level block (workflow.yml:110–111; `engine.py:1184–1186`), so the judge runs again. A model may not name the same departure twice, and then the user's ruling is refused with exit 1, or names a now-different path. | Validate a ruling deterministically against the asked record: folder listed, record governing in that folder in this check, path among the artifact's paths. Then honour it if the judge names that departure, and ignore it if not. |
